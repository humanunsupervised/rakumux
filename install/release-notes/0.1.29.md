# Rakumux 0.1.29

## Sessions on your own Fly.io Sprite

- Press `N` (or click `☁ Sprite` at the right of `+ New session`) and new sessions in that folder
  run on your own [Fly.io Sprite](https://sprites.dev): a Linux VM that pauses when nothing
  happens and keeps its files. `n` then starts one there. `N` again brings the folder's new
  sessions back to this machine.
- The first time, Rakumux sets the Sprite up with your Sprites token: one the `sprite` CLI saved
  on this computer, or one you make at sprites.dev/account and paste. It creates the Sprite,
  installs Rakumux there and connects, step by step. The token stays on this computer; the Sprite
  gets a Rakumux token of its own.
- A session on the Sprite has `☁` before its name and is listed under the folder you started it
  from. Going in is its live terminal on the Sprite. It runs in a folder of the same name in the
  Sprite's home, and for a git repository `git clone <origin> .` is typed there for you to run.
- While an agent works on the Sprite, Rakumux keeps the Sprite from pausing. Once none is, it
  pauses and costs little, and its sessions come back when you open one.
- From the command line: `rakumux sprite connect` sets the Sprite up, `rakumux new --sprite` runs
  a session there, and `rakumux machine add | ls | rm` lists the sessions of any other machine
  running Rakumux here, through its `rakumux-api` remote listener.

## Also

- `rakumux-api` serves `/v1/daemon` on its remote listener: the server's own protocol, for another
  machine's Rakumux.
- A server started without `SHELL` (as a service) starts your login shell in new sessions, not
  `/bin/sh`.

## Upgrading

`U` installs the update and reloads the UI. Sessions on a Sprite need the new server: press `S` in
Rakumux mode, then `y` (or run `rakumux daemon restart`) to restart it in place. Your sessions keep
running.
