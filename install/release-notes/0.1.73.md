# Rakumux 0.1.73

## Busy machines stay responsive

- With many sessions printing at once, the server kept up with each session's output but could
  put off its own periodic work for seconds: noticing a branch change, starting a heartbeat that
  was due, typing a new session's first prompt, or picking up a quiet agent's reply. That work
  now runs on time however busy the sessions are.
- An agent waiting on one session (`wait_for_session`) is no longer woken by every other
  session's output, and the server handles a burst of one session's output once instead of for
  every line: less work for the same result.
