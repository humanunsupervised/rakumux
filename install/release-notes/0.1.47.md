# Rakumux 0.1.47

## Terminal panel

- Each session has its own terminal panel. Switching sessions shows that session's panel as you
  left it, open or hidden, and never another session's.
- The panel holds tabs: its first shell is tab `1`, and `+` on the panel's bar opens another in
  the session's folder. A tab closes when its shell exits; the last one closes the panel.
- Settings shows the panel's keys: `T`, and `-` (below) or `|` (beside) next to the placement.

## Session list

- A session's second line starts with the repositories it works in, in bold and
  comma-separated: the one it started in first, then the one it's in now, then where it changed
  files. Each is named by its `origin` remote, else its folder.
- A session gets its AI title once a program started there (anything but a shell) has run 5 s;
  an agent waits for its first prompt, so it's titled from that.
- Under Status, ready sessions are grouped by when you last read them in finer steps: the last
  hour, the last 2, 4, 8, 12 and 24 hours, then older.

## Layouts

- The Grid layout is gone: `v` switches between Master detail and Tabs.

## Fixes

- A restart in place that fails no longer leaves the window disconnected, and trying again
  never stops the server and its sessions.
- Keys, clicks and paste no longer stop working when the selection moves while a session is
  opening.
- `z` no longer leaves the next session zoomed when going in fails.
- A divider being dragged when a dialog opens no longer swallows the next clicks.
- Scrolling back down to the live screen drops a selection made in the history.
- A window that can't take control of a session leaves the one in control as it was.
- Another machine reached for one request no longer shows as connected until restart.
- Cursor: a chat file written again no longer sends its old replies to the feed.
- GitHub Copilot: places after its log is rewritten are read from the right folder.
- `rakumux-api` acts for agent conversations after a restart in place that added them.
- The account service no longer sends sign-in, sign-out or title requests twice after a lost
  connection, and a sign-in renewal asked for while signed out no longer runs at the next
  sign-in.
- `rakumux remote pair` repairs a bad remote token, and no longer restarts the API at every
  call while `listen` is set.
