# Rakumux 0.1.34

## Seven more agents

GitHub Copilot, Cursor, Pi, Grok, Kimi Code, Droid and Amp now get what Claude Code, Codex and
OpenCode have:

- the session list shows when each is working, needs you or is done, in a colour of its own;
- its replies and whole chats in the Agent feed and on rakumux.com, and your replies typed back
  into it;
- where it changed files (`w`);
- the same conversation again after a crash or a reboot;
- **+ New session** on rakumux.com starts any of them.

Most of it works with nothing installed. Hooks, a plugin or an extension make the status exact
and name the conversation; install the one for your agent, then restart it inside Rakumux:

| Agent | Install |
|---|---|
| GitHub Copilot | `rakumux session hook-config --agent copilot --install` |
| Grok | `rakumux session hook-config --agent grok --install` |
| Cursor | `rakumux session hook-config --agent cursor-agent`, merged into `~/.cursor/hooks.json` |
| Droid | `rakumux session hook-config --agent droid`, merged into `~/.factory/hooks.json` |
| Pi | `rakumux-mcp pi-plugin --install` |
| Kimi Code | `rakumux-mcp kimi-plugin --install` |
| Amp | `rakumux-mcp amp-plugin --install` |

- Amp keeps its threads on ampcode.com, so its replies, chats and places need the plugin: it
  keeps a private copy of each thread on this machine for 30 days.
- Grok runs hooks only in folders you trusted. Kimi Code needs `kimi` on your `PATH` to come
  back after a reboot.
- To give an agent Rakumux's MCP tools, see `mcp/README.md`.

## Replies while an agent works

- A reply from rakumux.com or another machine now reaches Claude Code, Codex, OpenCode, Pi,
  GitHub Copilot, Grok and Kimi Code while they work, not only once they wait: each takes it at
  its next step, or as its next prompt when the turn ends.
- A reply is never typed into a permission prompt, question or menu: Rakumux waits until the
  agent asks nothing, and holds back its Enter if one opens as the reply goes in.
- Several replies to an agent that never stops (background subagents, one turn after another)
  each go in as soon as it took the one before; the second no longer waits for a quiet moment
  that never comes.
- The turn a reply was typed into keeps its own answer in the feed, even when the agent starts
  on the reply the moment that turn ends. Of several replies the agent takes within one turn,
  the last one taken gets the turn's answer.

## npm

- Every release is on npm too: `npm install -g rakumux`. Update it the same way, or with `U`.

## Fixes

- An agent revived after a crash or a reboot showed no latest line or chat, and could lose its
  resume command, until its screen changed again. Rakumux now reads it anyway.

## Upgrading

`U` installs the update and reloads the UI. Press `S` to restart the server in place (sessions
keep running) so it knows the new agents and guards replies from prompts.
