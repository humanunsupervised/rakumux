# Rakumux 0.1.44

## Session history

- Deleting a session no longer loses it. Settings → Session history (or `H`) lists the sessions
  you deleted, newest first, with a search field on top; Enter brings one back into its folder
  and revives it with its resume command, so its agent's conversation picks up where it was.
  Deleted sessions are kept 90 days, then removed for good.
- `rakumux history [query]` lists them and `rakumux restore <id|name>` brings one back.
- Needs the new server: press `S` once after updating (sessions keep running).

## rtop

- rtop graphs CPU, memory and network over time, the way btop does: the machine with Rakumux's
  share of it, then a graph beside each Rakumux process and session, and the selected one's
  CPU, memory and network in a panel of its own. The last 5 minutes are kept while the window
  is open, also while rtop is hidden.

## Fixes

- Selecting text in Claude Code's full-screen mode didn't copy it when you let go of the mouse
  outside the session (over the list, the footer or the divider). The release now reaches the
  program that took the press, wherever it lands, so its copy reaches your clipboard, over SSH
  too. Copying over SSH needs a terminal that allows OSC 52 (iTerm2: Settings → General →
  Selection → "Applications in terminal may access clipboard"; Ghostty, WezTerm and kitty allow
  it already; Apple's Terminal can't).
- Rakumux's copies reach the clipboard when it runs inside tmux or GNU screen, and a program in
  a session no longer formats its copies for a screen it isn't in.
- Agents' hooks failed with `rakumux.sh: not found` after you removed the install that started
  the server (switching from npm to the curl installer, say). The server kept handing new
  sessions that install's path; it now gives them the one Rakumux you started them from while
  its own is gone. Sessions started before the update keep the old path until restarted.
