# Orchestra 0.6.0

Orchestra is now a session manager for terminals and coding agents. Sessions run in a background
server and appear in one screen: a list of your sessions, grouped by folder, on the left and the
live session on the right.

## What's new

- **Sessions instead of worktrees.** A session is a folder plus a terminal: your login shell, a
  command you choose, or a coding agent such as Claude Code, Codex or OpenCode.
- **Folders.** Every session belongs to the folder it was started in: a repository, a worktree or
  any folder. Orchestra shows all folders at once, grouped under a header per folder; the filter at
  the top of the list (`P`) narrows it to one or several folders.
- **Your order.** Sessions stay where you put them: drag one, or press `J`/`K`, to move it.
- **Pinning.** `p` pins a session to the top of its folder.
- **Branch at a glance.** Each session shows its git branch and, in a linked worktree, the worktree
  name. Orchestra reads this from the repository's files and never runs git itself.
- **They keep running.** Sessions live in a background server (`orchestra-ptyd`), one per user on
  the machine, and keep running when you quit Orchestra, close the window or lose an SSH
  connection. Orchestra connects to the running server from any login (SSH, mosh, your phone) and
  starts it only when none runs; `orchestra --new-server` replaces it.
- **Restarts keep your work.** Restarting the server (`orchestra daemon restart`, or to pick up an
  upgrade) hands every running program to the new one: nothing stops, and Orchestra reconnects
  you to the session you were in. After a crash or a reboot, the sessions that were running come
  back by themselves: Claude Code, Codex and OpenCode reopen the same conversation with the same
  flags, and any other program's command waits at the prompt for you to run it again.
- **Live, interactive sessions on screen.** Select a session to watch it; press Enter to type into
  it. Several Orchestra windows can watch the same session at once.
- **The size follows the window you're using.** A session shown in several windows takes the size
  of the one you're using: a key, a click or switching to that window fits the session to it, while
  someone typing in another window keeps their size.
- **Two layouts**: a sidebar list (default) or tabs across the top. Switch in Settings (`o`). Drag
  the line between the list and the session to resize the list.
- **Phones.** Under 80 columns, Orchestra mode is the session list alone: tap a session to open it
  full screen under a row of session tabs (tap a tab to switch), and `Ctrl-\` goes back to the
  list.
- **Two modes, one key.** In a session every key goes to the program except `Ctrl-\`, which
  coding agents and editors leave alone. It switches to Orchestra mode, where arrows and Vim keys
  (`j`/`k`, `gg`/`G`, `Ctrl-d`/`Ctrl-u`) move through sessions while they show live, `Enter` goes
  in, `Esc` goes back, `Tab` jumps to the previous session and single letters do the rest (`n`,
  `r`, `p`, `x`, `dd`, `z`, `/`, `?`, `,`). `Option`/`Alt` + `↑`/`↓` switch sessions in Orchestra
  mode, and inside sessions too if you turn it on. Settings' Keys tab lists and runs every action;
  `?` opens Help.
- **Arrow keys over slow links.** Arrows work in Orchestra mode over slow connections such as
  Termius on a phone, where a key's bytes can arrive in pieces: a lone Esc waits up to 300 ms for
  the rest of the key instead of acting as Esc.
- **Icons to suit your terminal.** Folders and branches are marked with plain symbols by
  default; Settings switches them to emoji or Nerd Font icons.
- **Agent awareness.** Orchestra recognises common coding agents and shows whether each one is
  working, waiting for you or done.
- **Command line**: `orchestra new`, `ls` (`--folder`, `--all`, `--dead`), `attach`, `rename`,
  `kill`, `rm`, `pin`/`unpin`, `folders [add|rm]`, `daemon start|status|stop|restart|logs`, and
  `orchestra session …` (JSON, for scripts and agents running inside sessions).
- **For coding agents: an MCP server.** `orchestra-mcp` lets agents list folders, find sessions by
  id or name, create sessions, read a session's screen and rename sessions. An agent running inside
  an Orchestra session can start sessions in its own folder (a few at a time). Install it with e.g.
  `claude mcp add --scope user orchestra -- orchestra-mcp`. For OpenCode 2.x, also run
  `orchestra-mcp opencode-plugin --install` so its tool calls act as the Orchestra session the
  conversation runs in. It talks to `orchestra-api`, a local HTTP
  API (127.0.0.1 only, token-protected) that scripts can use too.
- **Input log for key problems.** `orchestra --debug` logs the input events Orchestra reads to
  `~/.orchestra/logs/tui-input.log`, and every quit writes the last 500 there, so a key problem can
  be looked at after it happens. Keys typed into a session are logged only as "(session key)".
- **AI naming** now uses Claude Haiku 5.5 (the model 0.5.x used was retired by Anthropic).

## Breaking changes

- **tmux is no longer used, and sessions from 0.5.x are not supported.** Orchestra 0.6.0 doesn't
  show, attach to or migrate tmux sessions created by earlier versions. They keep running in tmux
  until you end them: list them with `tmux ls` and close them with `tmux kill-session -t <name>`
  (or `tmux kill-server` to end all tmux sessions).
- **No git operations.** Worktree creation, git status, merge helpers, env-copy and `orchestra-cli`
  are gone; Orchestra only reads the branch name to show it. Sessions work in any folder, git
  repository or not.
- **Remote/cloud mode is gone.**
- **No longer needed:** `tmux`, `git` and `jq`.

## Upgrading

1. Upgrade as usual (`npm i -g @humanu/orchestra` or `brew upgrade orchestra`).
2. If you added the `orchestra()` or `orchestra-cli()` shell functions from the old docs to your
   shell profile, remove them; `orchestra` works directly.
3. Optional clean-up of 0.5.x leftovers:
   - `.orchestra/cloud.json`, `.orchestra/ssh.json` and `.orchestra/worktree.json` inside your
     repositories (remote mode metadata);
   - a DigitalOcean token stored in your OS keychain by remote mode;
   - the old session registry entries are removed automatically on first start.
